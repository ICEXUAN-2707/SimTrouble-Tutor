# SimTrouble Tutor 当前阶段简版 PRD

> 版本：v0.4-next  
> 日期：2026-10-11  
> 阶段：CAD 动画基础已完成，进入 LLM Tutor、诊断评分与 UI 收口阶段

## 1. 产品定位

SimTrouble Tutor 是面向工业机器人运维学习者的诊断式实训产品。系统通过
可重复的异常仿真，让学习者经历“观察现象—提出假设—检查证据—修正判断—
提交诊断—获得反馈”的完整过程，并由 AI Tutor 提供个性化引导，由程序生成
可解释的能力评分。

当前阶段只需围绕 ST-001 跑通一个完整、稳定、可演示的学习闭环。

## 2. 当前基础

已完成：

- Three.js 工业机器人工作站；
- ST-001 Case 驱动的确定性抓取失败动画；
- CAD 风格网格、坐标轴、正交镜头和基础播放控制；
- FastAPI Scene API；
- Case、Session、Evidence、Trace 等 Core 基础；
- Tutor、Diagnosis、Evaluator、Report v0.4 契约。

尚未完成：

- 后端 LLM API 实际调用；
- 新版 Session、Evidence、Tutor、Diagnosis、Report API；
- 基于学习过程的正式评分；
- 个性化诊断辅导；
- CAD 场景与学习闭环的前端集成；
- UI 的工业软件化收口。

## 3. 本阶段目标

1. 后端能够安全、稳定地调用 LLM，并在失败时自动降级到规则 Tutor。
2. 根据用户真实学习过程生成五维、可解释、可复算的能力评价。
3. 根据用户当前阶段、操作、回答和已查看证据提供个性化诊断辅导。
4. 将界面从通用“AI 应用”视觉调整为专业工业 CAD/工程软件视觉。
5. 完成一次可在 90–120 秒内演示的 ST-001 训练闭环。

## 4. 目标用户与场景

目标用户：工业机器人、自动化、机电相关专业学生及初级运维学习者。

典型场景：学习者看到机器人夹爪闭合但未抓起工件，通过观察动画、检查
E01/E02/E03、提出和修正假设，最终判断工件位置偏移，并获得诊断反馈和
能力报告。

## 5. 核心用户流程

`进入案例 → 播放异常 → 观察现象 → 提出假设 → 检查证据 → 询问 Tutor → 修正假设 → 提交诊断 → 查看评分与报告`

对用户公开的产品状态保持简单：

`READY → PLAYING → INVESTIGATING → SUBMITTED → REVIEWED`

内部九阶段 Core 状态不直接暴露给普通用户。

## 6. 功能需求

### 6.1 后端 LLM API 接入

后端增加与厂商无关的 LLM 调用层，并提供 OpenAI-compatible Adapter。

必须满足：

- API Key、Base URL、模型名通过环境变量配置，不写入代码或前端；
- Tutor 请求只包含 Public Case、已释放 Evidence、用户消息、假设和允许动作；
- 使用结构化 JSON 输出，并由 Pydantic 严格校验；
- 支持超时、有限重试、错误记录和规则 Tutor 自动回退；
- 模型输出疑似泄漏未公开答案时，丢弃该输出并回退；
- 前端不直接调用模型服务；
- Ground Truth 和评分规则仅允许在用户提交诊断后的 Evaluator 模式使用。

### 6.2 个性化诊断辅导

Tutor 根据以下信息动态调整反馈：

- 当前学习阶段；
- 已查看 Evidence；
- 当前及历史假设；
- 重复或无关操作；
- 用户回答内容；
- 已使用提示次数；
- 当前允许执行的下一步动作。

辅导策略：

- 优先追问观察和依据，不直接公布答案；
- 用户没有假设时，引导形成可验证假设；
- 用户证据不足时，引导选择有区分度的检查项；
- 新证据与原假设冲突时，引导明确修正；
- 用户连续走错方向时逐级提高提示强度；
- 用户已经形成充分证据链时，提示其提交诊断；
- 每次回答应给出一条明确但不越权的建议动作。

### 6.3 正式诊断

诊断提交包含：

- 结构化诊断类别；
- 文字推理依据；
- 引用的 Evidence ID。

提交后才允许 Evaluator 读取 Ground Truth。旧 Demo 的关键词判断不得进入正式
判定路径。重复提交不得重复评分或产生第二份权威报告。

### 6.4 学习过程评分

报告评价五个维度：

| 维度 | 主要依据 |
|---|---|
| Hypothesis | 是否提出明确、可验证的假设 |
| Evidence | 是否检查并引用有区分度的证据 |
| Efficiency | 是否存在大量重复、无关或无效操作 |
| Updating | 获得新证据后是否主动修正判断 |
| Safety | 是否完成 Case 中可观察的安全行为 |

评分规则：

- LLM 只提供定性发现和反馈文字，不直接决定数字分数；
- 程序根据版本化规则、Trace 和固定权重计算分数；
- 每个分数必须关联规则、理由及 Trace 位置；
- 相同 Case 和相同 Trace 必须得到相同结果；
- 没有评价机会的维度显示 `not_assessed`，分数为 `null`，不得记为 0 分；
- ST-001 当前没有安全交互时，Safety 默认 `not_assessed`。

### 6.5 学习报告

报告至少展示：

- 用户提交的诊断与系统判定；
- 参考解释；
- 使用过的 Evidence；
- 关键学习路径；
- 五维能力结果、理由和评价覆盖度；
- 本次做得好的地方；
- 下一步建议；
- 本轮使用 LLM Tutor 或规则回退的透明标识。

## 7. UI 与 CAD 视觉要求

设计目标是“工业诊断工作站”，而不是“聊天机器人页面”。

### 7.1 视觉语言

- 主色使用深灰、石墨色、冷白和低饱和工程绿；告警只使用少量橙色；
- 减少大面积渐变、发光、玻璃拟态、圆润卡片和装饰性 AI 图标；
- 使用细边框、工程刻度、坐标、尺寸标注、状态码和等宽数字；
- 卡片圆角尽量小，层级主要依靠线框、留白、灰度和标题编号；
- Tutor 改造成“诊断指导台/工程助手”，弱化聊天气泡感；
- 页面核心视觉始终是 CAD 场景，AI 辅导和评分作为辅助面板存在。

### 7.2 场景交互

- 保留正交镜头、网格、坐标轴、边线和视图工具；
- 支持播放、暂停、继续、跳过、重播、重置、旋转、平移、缩放和适配视图；
- 动画时间线展示关键步骤和当前设备状态；
- 只有在相应 Evidence 已释放后，才显示位置偏差、测量线和数值；
- 补齐 `object_attached` 表现，为后续成功抓取 Case 做准备；
- 动画播放、暂停和重播不得改变 Session、Trace 或能力评分。

### 7.3 页面布局

- 中央：CAD 仿真视口；
- 右侧：任务、状态、公开观察、Evidence 和诊断指导；
- 底部：动画时间线和控制；
- 诊断提交后：使用工程报告面板展示结果，不弹出娱乐化成功动画；
- 适配 1280×720、768×1024 和 390×844。

## 8. 非功能与安全要求

- Tutor 永远看不到未释放 Evidence、Ground Truth、Optimal Path 和评分规则；
- 前端源码、初始接口、日志和错误信息不得泄漏 ST-001 真因；
- Session 之间 Evidence、消息、诊断和报告必须隔离；
- LLM 不可用时，用户仍可依靠规则 Tutor 完成训练；
- 所有模型输出必须验证后才能展示或参与后续流程；
- API Key 不得出现在 Git、浏览器包或 HTTP 响应中；
- 当前使用进程内 Session，不要求账号、数据库或跨设备同步。

## 9. 本阶段不做

- 多 Agent 协作；
- 模型微调；
- LLM 直接打分；
- 真实机器人控制；
- Isaac Sim/Gazebo 物理仿真；
- 多用户管理后台；
- 大规模 Case 编辑器；
- 长期学习数据持久化。

## 10. MVP 验收标准

1. 浏览器可以完整完成 ST-001 从动画到学习报告的流程。
2. 后端真实调用一次配置的 LLM；超时、无效 JSON 和泄漏测试均能回退。
3. Tutor 请求中不存在任何私有 Case 字段。
4. 用户操作和回答能够改变 Tutor 的提问、提示强度和建议动作。
5. 正确与错误诊断都能得到结构化、证据化反馈。
6. 相同 Trace 重算报告时，数字分数完全一致。
7. Safety 无评价机会时显示 `not_assessed`，而不是 0 分。
8. 动画重播前后 Session、Trace 和评分不变。
9. 桌面、平板和手机视口均能完成主流程。
10. Python 回归、前端生产构建和浏览器 E2E 全部通过。
