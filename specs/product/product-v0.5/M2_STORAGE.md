# M2：最小训练记录持久化

日期：2026-10-26。依据本轮用户确认收敛范围，取代 `M2_STORAGE_DRAFT.md` 中的扩展设想。
开发基于已通过本地及远端验收的 M0 分支，合入 Phase 时仍须遵守 M0 → M2 的顺序。

## 完成目标

登录用户完成训练后，SQLite 保存一条训练记录；API 重启后，原用户可以通过已有
Session ID 读取同一份已完成训练和报告。不同用户及匿名接口不能读取该记录。

## 固定实现边界

- 复用现有 SQLite 文件和初始化入口；不新增服务、依赖或配置项。
- 只加 `training_records` 一张表：Session ID（主键）、用户 ID、Case ID、完成时间、
  公开 SessionView JSON、TrainingReportV04 JSON。训练过程只保存现有公开证据和假设快照。
- 只实现 `save_completed` 与 `get_completed`，读取必须同时匹配 Session ID 和用户 ID。
- 只有账号所属训练完成时写入一次；匿名训练和未完成训练保持原状。
- 在现有诊断完成原子回调内保存，写入失败则本次提交失败，内存状态不完成，允许重试。
- 数据库按现有版本号从 v2 增量到 v3，不清空账号或已有认证数据。
- 重启后的读取复用现有 GET Session 与 Report 路由和响应模型；重复诊断保持 409。
- 记录只读，不从记录恢复可操作的训练会话。

不做历史列表接口/页面、分页、搜索、统计、导出、删除、续训、Tutor 对话保存、
完整 Trace 存储、事件溯源、队列、ORM、通用存储框架或多数据库兼容。
不更改 CAD、Core、Tutor、评分、公开 Schema、Cookie 和认证规则。

## 执行顺序

1. 存储：新增小型 `training_records.py`，给现有 SQLite 初始化补一张表。
2. 接入：诊断完成时保存；已有 GET 接口在内存中找不到时读取所属用户的完成记录。
3. 验证与交付：重启读取、用户隔离、写入失败重试、重复提交；完整回归和现有浏览器流程。

涉及 `auth/repository.py`、`training_records.py`、`session_service.py`、
`evaluation/service.py`、`main.py`；测试集中在 `tests/v0_5/test_training_records.py`，
现有迁移测试同步数据库版本断言。前端无需增加页面或业务逻辑。

## 验收即停止

- 完成一次训练只写一条记录，报告和公开训练快照一起保存。
- 新 API 实例使用同一个 SQLite 文件，登录原账号后可读到相同记录和评分。
- 其他用户、未登录用户及匿名 v0.4 接口不可读取。
- SQL 写入失败不推进会话或留下报告，恢复数据库后原请求可重试。
- 重复提交不覆盖已有记录；未完成训练不写入、也不恢复。
- 现有账号数据及认证不受影响；全部 Python 和现有浏览器回归通过。

上述项通过后 M2 完成，不继续追加功能。通过训练 ID 读取是本轮边界；
产品界面仍按现有行为创建新训练，不在本轮添加“我的历史训练”入口。
