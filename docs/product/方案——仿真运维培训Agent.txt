# SimTrouble Tutor 简版 PRD

## 一句话介绍

**SimTrouble Tutor 是一个面向工业机器人运维学习者的仿真驱动故障排查训练智能体，通过在虚拟机器人环境中构造可控异常，让 AI Tutor 引导用户完成“观察—假设—检查—修正—诊断”的排障过程，并形成个人能力画像。**

---

## 一、项目背景

随着工业机器人、具身智能设备进一步进入制造现场，企业不仅需要“会编程、会操作机器人”的人员，也越来越需要能够处理异常、理解设备状态并完成基础故障排查的运维人员。

但工业机器人故障训练存在几个现实限制：

- 真实机器人设备昂贵，教学资源有限；
- 故意制造故障可能带来设备损坏和人员安全风险；
- 很多异常工况难以重复、规模化构造；
- 专家经验有限，很难做到长期一对一指导；
- 传统虚拟实训更多训练“按照固定步骤操作”，对真实排障中最重要的诊断思维训练不足。

与此同时，机器人仿真平台已经能够在虚拟环境中构造机器人任务、改变环境参数并记录设备状态。

因此，本项目希望把：

> **机器人仿真产生的异常场景**

进一步转化为：

> **可以训练人的故障排查案例。**

项目不尝试替代真实维修工程师，也不直接控制真实机器人，而是首先解决：

> **如何低成本、安全、可重复地训练工业机器人异常处置能力。**

---

## 二、核心痛点与价值

### 1. 现有培训更容易教“怎么做”，但较难训练“怎么判断”

真实排障并不是简单记忆：

> 出现故障 A → 执行动作 B。

更常见的过程是：

> 发现异常  
> → 判断需要查看哪些信息  
> → 提出可能原因  
> → 进行检查  
> → 获得新证据  
> → 排除错误原因  
> → 更新判断  
> → 最终定位问题。

因此项目重点训练的不是标准操作流程，而是：

**Diagnostic Reasoning——基于证据逐步排查问题的能力。**

---

### 2. 真实故障案例获取困难

如果直接做真实维修 Agent，需要：

- 企业设备数据；
- 历史维修案例；
- 专家经验；
- 大量真实故障标签。

这些数据对学生团队很难获得。

本项目通过仿真主动注入异常，因此每个训练案例天然知道：

> 故障是什么、参数是多少、机器人发生了什么。

这样就能得到明确的 Ground Truth，用于训练和评价，而不依赖企业私有数据。

---

### 3. 传统培训通常只看最终答案

两个学习者最后都答对，不代表能力相同。

一个人可能通过合理证据逐步排查得到答案；另一个人可能随机尝试。

因此系统除了判断结果，还记录完整诊断路径，并从以下维度评价：

- 假设提出能力；
- 证据选择能力；
- 排查效率；
- 根据新证据修正判断的能力；
- 安全意识。

最终形成个人技能画像，并推荐下一训练案例。

---

## 三、技术实现

整体技术链路：

```text
机器人仿真场景
      ↓
异常注入
      ↓
记录机器人状态与结果
      ↓
生成带 Ground Truth 的训练 Case
      ↓
AI Tutor 引导学员排查
      ↓
记录完整诊断过程
      ↓
能力评分与学习反馈
```

### 1. Simulation / Scenario Layer

第一版选择一个简单的：

**工业机器人柔性搬运工作站。**

包含：

- Robot Arm；
- Gripper；
- Workpiece；
- Target Area；
- Obstacle。

首批只设计 4 类异常：

1. 物体位置偏移；
2. 抓取失败；
3. 障碍物 / 碰撞风险；
4. 放置目标冲突。

V0阶段可以先通过简单状态机或轻量动画模拟。

后续再接入：

- Isaac Sim；
- Gazebo；
- RobotStudio；

等成熟机器人仿真平台。

---

### 2. Fault Case Engine

这是项目核心模块之一。

每一个故障案例都保存结构化信息，例如：

```text
任务是什么
故障类型
故障参数
初始可见症状
可查询证据
隐藏证据
真实原因 Ground Truth
推荐排查路径
安全规则
评分规则
```

例如：

> 真实物体位置比机器人计划抓取位置偏移 70 mm。

学习者一开始不知道这个真因，只会看到：

> 机器人运动完成、夹爪闭合，但没有抓到物体。

随后通过主动检查证据逐渐发现问题。

---

### 3. AI Tutor Agent

AI不直接告诉学习者答案。

它主要负责：

- 追问学习者当前判断；
- 根据用户选择返回相应证据；
- 判断是否需要提示；
- 当学习者走错方向时进行苏格拉底式追问；
- 根据学习者水平控制提示强度；
- 训练结束后进行复盘。

典型流程：

```text
发现异常
↓
选择检查项
↓
获取证据
↓
提出假设
↓
继续检查
↓
根据新证据修改假设
↓
提交诊断
```

Agent可以使用 LangGraph 等状态式 Agent 框架管理学习过程。

---

### 4. Skill Model

系统记录用户全过程，而不是只记录最终答案。

初版采用规则评分即可，形成五维能力：

```text
Hypothesis
Evidence
Efficiency
Updating
Safety
```

例如：

- 选择高价值证据：Evidence 加分；
- 重复进行无关检查：Efficiency 扣分；
- 新证据出现后及时修正假设：Updating 加分；
- 忽视安全风险：Safety 扣分。

训练结束生成：

> 能力画像 + 本次排查路径 + 推荐下一案例。

---

### 5. V0技术栈建议

前端：

> React / Next.js

后端：

> Python + FastAPI

Agent：

> LangGraph + 成熟 LLM API

数据库：

> SQLite

知识库：

> Markdown / PDF + BM25 / Vector Retrieval

仿真：

> V0先使用轻量状态模拟；后续按开发进展接 Isaac Sim / Gazebo。

---

## 四、V0目标

第一版只需要完成：

> **1个柔性搬运工作站 + 4类异常 + 12—20个训练案例 + 1个AI Tutor + 5维能力画像。**

用户能够完整体验一次：

> **异常出现 → 查看证据 → 提出假设 → 排查 → 修改判断 → 提交诊断 → 获得能力反馈。**

项目当前不追求：

- 真实企业级机器人维修；
- 自动控制机器人；
- 最终根因自动诊断；
- 大规模模型微调；
- 真实企业维修数据接入。

V0首先验证：

> **“仿真异常 + AI诊断式教学”是否能够形成一个完整、可交互、可评价的工业机器人故障训练闭环。**
