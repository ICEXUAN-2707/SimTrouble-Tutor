1. 产品基线：保留 develop 上已审核的 v0.4 → v0.5 合并历史，涵盖训练、
   Tutor、诊断报告、认证隔离、完成记录与本地启动器（PR #28–#30）。

5. 集成发布：PR #31 通过当前 head 检查后进入 develop；再经 develop → main
   发布 PR，使用 merge 保留以上历史，不 rebase、不强推。最终 main 合并后复核 CI。

## 已包含

- Vite/TypeScript/Three.js 中文响应式工作台，ST-001 动画与确定性训练流程。
- Evidence → Hypothesis → 修订 → Diagnosis → 五维 Report，重复提交与错误恢复。
- FastAPI 认证、CSRF、用户隔离；SQLite 账号、认证会话和完成训练记录。
- Tutor Policy + Provider + 输出安全检查 + 规则回退；模型不能修改权威状态或评分。
- Windows 启动器、Linux systemd/Nginx 模板、SQLite 在线快照与拒绝覆盖的恢复命令。

## 使用入口

- 本地：根 README 的 Product v0.5 启动步骤，默认规则 Tutor，无密钥也可训练。
- 真实模型：在受保护环境配置启用开关及 DEEPSEEK_API_KEY，执行
  `python tools/deepseek_tutor_smoke.py`；不要把密钥提交到仓库。
- 服务器：[deploy/README.md](../../deploy/README.md)，域名/证书需替换，API 单 worker。
- 备份：`python tools/sqlite_backup.py --help`；restore 只写新路径并撤销旧认证会话。

## 已知限制及回滚

活动训练与对话在内存，重启会丢失；没有历史列表、续训或真实物理仿真。
多 Case 是后续路线图，当前稳定验收案例为 ST-001。仅 DeepSeek 在本轮真实调用验证。
发布准备未改变 schema 3；回滚须先停写并判断 schema 兼容性，保留故障现场。
从备份恢复会丢失备份之后的数据，需确认影响并要求用户重新登录。
