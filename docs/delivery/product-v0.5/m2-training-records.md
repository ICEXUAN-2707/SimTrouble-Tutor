# M2 交付：最小用户训练记录存储

日期：2026-10-26。分支：`task/product-v0.5-m2-training-records`。
基线：M0 验证分支 `0e3a247`；合入 Phase 前需先完成 M0 PR #24。
范围依据用户本轮确认及 [M2_STORAGE.md](../../../specs/product/product-v0.5/M2_STORAGE.md)。

## 实现

复用 `var/auth.db`（或已有 `SIMTROUBLE_AUTH_DB_PATH`），新增一张 `training_records` 表，
按用户保存已完成训练的案例、完成时间、公开证据/假设快照和最终报告。
新模块只有 `save_completed`、`get_completed` 两个操作。
现有初始化器自动将 SQLite v2 增量升级到 v3，保留账号与认证数据。

保存发生在既有诊断完成的原子回调内，SQL 失败则内存训练状态和报告不提交，
恢复数据库后可重试。Session ID 为主键，重复诊断不能覆盖记录。
服务重启后，原用户通过已有 GET Session/Report 接口及原 Session ID 读取记录。
读取同时匹配用户 ID，跨用户与匿名请求不能绕过所有权限制。

没有新增依赖、服务、配置项、公开路由、Schema 或前端业务改动。
没有增加历史列表、统计、导出、续训、Tutor 对话或完整 Trace 存储。
现有界面刷新后仍创建新训练；本轮不提供历史入口。
